Encrypted
Voting System

On-chain voting today is broken by design — anyone can see how delegates vote, creating coercion risk and strategic voting. Today you build a private voting system where individual votes are hidden until after the poll closes, using FHEVM to tally results without ever revealing individual choices.

⏰ 4–5 hours

Why Encrypt Votes?

Public on-chain voting has three serious problems:

  • Coercion — voters can be bribed or threatened based on their visible vote history
  • Strategic voting — voters change behavior when they can see others' votes in real time
  • Front-running — late voters have unfair information advantages over early voters
🔒
FHEVM Solution
Individual votes are encrypted with ebool. The tally contract accumulates encrypted YES/NO counts using FHE.add(). Nobody can see vote counts until the poll closes. After closing, the owner requests public decryption via the Gateway — revealing only the aggregate totals, never individual votes.

Proposal Lifecycle

Phase 1
🔧 Created
Proposal exists, voting not yet open. Owner sets title, description, and voting window.
Phase 2
✅ Active
Voting open. Eligible voters cast encrypted votes. Tally accumulates silently.
Phase 3
🔒 Closed
Voting window ended. Owner calls requestTally(). No new votes accepted.
Phase 4
📈 Tallied
Gateway callback delivers plaintext totals. Results are public and final.

The PrivateVoting Contract

Storage Layout & Events

Soliditycontracts/PrivateVoting.sol — storage
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import "@fhevm/solidity/lib/FHE.sol";
import "@fhevm/solidity/config/ZamaConfig.sol";
import "@fhevm/solidity/gateway/GatewayCaller.sol";

contract PrivateVoting is ZamaEthereumConfig, GatewayCaller {

    enum ProposalState { Created, Active, Closed, Tallied }

    struct Proposal {
        string        title;
        string        description;
        uint256       startTime;
        uint256       endTime;
        euint32       yesCount;    // encrypted running total
        euint32       noCount;     // encrypted running total
        uint32        totalVoters; // plaintext count of who voted (not how)
        ProposalState state;
        // Results after tally (plaintext, only set post-reveal):
        uint32        finalYes;
        uint32        finalNo;
    }

    mapping(uint256 => Proposal)    public  proposals;
    mapping(uint256 => mapping(address => bool)) private hasVoted;
    mapping(address => bool)        public  isEligible;
    mapping(uint256 => uint256)     private tallyRequestId; // requestId → proposalId
    mapping(uint256 => uint256)     private requestToProposal;

    uint256 public proposalCount;
    address public immutable owner;

    event ProposalCreated(uint256 indexed id, string title);
    event VoteCast(uint256 indexed proposalId, address indexed voter);
    event TallyRequested(uint256 indexed proposalId, uint256 requestId);
    event ResultRevealed(uint256 indexed proposalId, uint32 yes, uint32 no);

    constructor() { owner = msg.sender; }

    modifier onlyOwner() { require(msg.sender == owner, "Not owner"); _; }
}

createProposal() and Voter Registration

SolidityPrivateVoting.sol — setup
function registerVoter(address voter) external onlyOwner {
    isEligible[voter] = true;
}

function createProposal(
    string calldata title,
    string calldata description,
    uint256 durationSeconds
) external onlyOwner returns (uint256 id) {
    id = proposalCount++;
    Proposal storage p = proposals[id];
    p.title       = title;
    p.description = description;
    p.startTime   = block.timestamp;
    p.endTime     = block.timestamp + durationSeconds;
    p.state       = ProposalState.Active;

    // Initialize encrypted tallies to 0
    p.yesCount = FHE.asEuint32(0);
    p.noCount  = FHE.asEuint32(0);
    FHE.allowThis(p.yesCount);
    FHE.allowThis(p.noCount);

    emit ProposalCreated(id, title);
}

castVote() — The Heart of Private Voting

Votes are submitted as encrypted booleans. We use FHE.select() to conditionally add 1 to either yes or no count — without the contract ever knowing which was chosen.

SolidityPrivateVoting.sol — castVote
/**
 * @notice Cast an encrypted vote on a proposal.
 * @param proposalId  Which proposal to vote on
 * @param encVote     Encrypted bool: true = YES, false = NO
 * @param proof       ZK proof binding ciphertext to this contract + caller
 */
function castVote(
    uint256       proposalId,
    externalEbool calldata encVote,
    bytes         calldata proof
) external {
    require(isEligible[msg.sender],       "Not eligible");
    require(!hasVoted[proposalId][msg.sender], "Already voted");

    Proposal storage p = proposals[proposalId];
    require(p.state == ProposalState.Active, "Not active");
    require(block.timestamp < p.endTime,       "Voting closed");

    // Validate input: ZK proof confirms this vote was encrypted for
    // this contract + this caller
    ebool vote = FHE.fromExternal(encVote, proof);

    // ONE = encrypted constant 1
    euint32 ONE  = FHE.asEuint32(1);
    euint32 ZERO = FHE.asEuint32(0);

    // If vote is YES: add 1 to yesCount, add 0 to noCount
    // If vote is NO:  add 0 to yesCount, add 1 to noCount
    // FHE.select(bool, ifTrue, ifFalse)
    euint32 yesAdd = FHE.select(vote, ONE,  ZERO);
    euint32 noAdd  = FHE.select(vote, ZERO, ONE);

    p.yesCount = FHE.add(p.yesCount, yesAdd);
    p.noCount  = FHE.add(p.noCount,  noAdd);

    // Grant contract access to both new handles
    FHE.allowThis(p.yesCount);
    FHE.allowThis(p.noCount);

    // Mark voter — this is public metadata, not the vote itself
    hasVoted[proposalId][msg.sender] = true;
    p.totalVoters++;

    emit VoteCast(proposalId, msg.sender); // no vote direction revealed
}
💡
Why FHE.select() Instead of Two Separate Conditions
We always add to both yesCount and noCount — adding either 1 or 0 depending on the encrypted vote. This means exactly one counter increments by 1, and the other stays the same, without the contract (or anyone watching) knowing which one changed. The coprocessor performs both additions off-chain; only the handles change on-chain.

requestTally() — Close and Reveal

SolidityPrivateVoting.sol — requestTally
function requestTally(uint256 proposalId) external onlyOwner {
    Proposal storage p = proposals[proposalId];
    require(p.state == ProposalState.Active, "Not active");
    require(block.timestamp >= p.endTime, "Voting still open");

    p.state = ProposalState.Closed;

    // Mark both handles as publicly decryptable
    FHE.makePubliclyDecryptable(p.yesCount);
    FHE.makePubliclyDecryptable(p.noCount);

    // Request both in a single Gateway call
    euint32[] memory handles = new euint32[](2);
    handles[0] = p.yesCount;
    handles[1] = p.noCount;

    uint256 reqId = Gateway.requestDecryption(
        handles,
        this.tallyCallback.selector,
        0,
        block.timestamp + 1 hours,
        false
    );

    requestToProposal[reqId] = proposalId;
    emit TallyRequested(proposalId, reqId);
}

// Gateway calls this with BOTH decrypted values
function tallyCallback(
    uint256 requestId,
    uint32  yesResult,
    uint32  noResult
) external onlyGateway {
    uint256 proposalId = requestToProposal[requestId];
    Proposal storage p = proposals[proposalId];

    p.finalYes = yesResult;
    p.finalNo  = noResult;
    p.state    = ProposalState.Tallied;

    emit ResultRevealed(proposalId, yesResult, noResult);
}

Reading Results

SolidityPrivateVoting.sol — result view
function getResult(uint256 proposalId)
    external view returns (
        uint32  yes,
        uint32  no,
        bool    passed,
        uint32  totalVoters
    )
{
    Proposal storage p = proposals[proposalId];
    require(p.state == ProposalState.Tallied, "Not tallied yet");

    yes         = p.finalYes;
    no          = p.finalNo;
    passed      = p.finalYes > p.finalNo;
    totalVoters = p.totalVoters;
}

// Anyone can check if a voter participated (but not HOW they voted)
function didVote(uint256 proposalId, address voter)
    external view returns (bool)
{
    return hasVoted[proposalId][voter];
}

Key Design Patterns

Preventing Double Voting Without Leaking Vote

💡
Public Participation, Private Choice
hasVoted[proposalId][voter] is a plaintext bool — it only records whether someone voted, not how. This is intentionally public: you can prove participation without revealing direction. The contract checks this before accepting a vote, preventing double-voting while keeping vote content private. This is analogous to a physical polling station verifying your ID but not recording your ballot choice.

Strict State Machine

StatecastVote?requestTally?getResult?
Created✗ Not active✗ Not active✗
Active✓ If within endTime✓ If past endTime✗
Closed✗ Closed✗ Already requested✗ Pending callback
Tallied✗✗✓ Results available

Tracking Quorum Without Revealing Counts

📈
totalVoters is Public
p.totalVoters is a plaintext counter that increments on every castVote() call. This lets anyone verify quorum was reached (enough people voted) without revealing the YES/NO split. A quorum check might require 51% participation before tally is allowed. This is intentionally public — you need to know how many voted to assess legitimacy, just not how they voted.

Test Suite

TypeScripttest/PrivateVoting.test.ts
import { ethers, network } from "hardhat";
import { expect } from "chai";
import { getFhevmInstance } from "./helpers";

describe("PrivateVoting", () => {
  let voting: any;
  let owner: any, alice: any, bob: any, carol: any;
  const DURATION = 3600; // 1 hour

  before(async () => {
    [owner, alice, bob, carol] = await ethers.getSigners();
    const F = await ethers.getContractFactory("PrivateVoting");
    voting = await F.deploy();
    await voting.waitForDeployment();

    // Register voters
    await voting.connect(owner).registerVoter(alice.address);
    await voting.connect(owner).registerVoter(bob.address);
    await voting.connect(owner).registerVoter(carol.address);
  });

  it("creates a proposal", async () => {
    const tx = await voting.createProposal(
      "Increase treasury allocation",
      "Should the treasury increase developer grants by 20%?",
      DURATION
    );
    await tx.wait();
    const p = await voting.proposals(0);
    expect(p.title).to.equal("Increase treasury allocation");
    console.log("  ✓ Proposal 0 created");
  });

  it("alice votes YES (encrypted)", async () => {
    const instance = await getFhevmInstance();
    const addr     = await voting.getAddress();

    // Encrypt vote: true = YES
    const input = instance.createEncryptedInput(addr, alice.address);
    input.addBool(true);   // YES vote
    const { handles, inputProof } = await input.encrypt();

    await voting.connect(alice).castVote(0, handles[0], inputProof);
    expect(await voting.didVote(0, alice.address)).to.be.true;
    console.log("  ✓ Alice voted (YES, encrypted)");
  });

  it("bob votes NO (encrypted)", async () => {
    const instance = await getFhevmInstance();
    const addr     = await voting.getAddress();

    const input = instance.createEncryptedInput(addr, bob.address);
    input.addBool(false);  // NO vote
    const { handles, inputProof } = await input.encrypt();

    await voting.connect(bob).castVote(0, handles[0], inputProof);
    console.log("  ✓ Bob voted (NO, encrypted)");
  });

  it("carol votes YES; totalVoters = 3", async () => {
    const instance = await getFhevmInstance();
    const addr     = await voting.getAddress();
    const input    = instance.createEncryptedInput(addr, carol.address);
    input.addBool(true);
    const { handles, inputProof } = await input.encrypt();
    await voting.connect(carol).castVote(0, handles[0], inputProof);

    const p = await voting.proposals(0);
    expect(p.totalVoters).to.equal(3n);
    console.log("  ✓ 3 votes cast. Individual votes are still hidden.");
  });

  it("double-vote is rejected", async () => {
    const instance = await getFhevmInstance();
    const addr     = await voting.getAddress();
    const input    = instance.createEncryptedInput(addr, alice.address);
    input.addBool(false);
    const { handles, inputProof } = await input.encrypt();
    await expect(
      voting.connect(alice).castVote(0, handles[0], inputProof)
    ).to.be.revertedWith("Already voted");
  });

  it("fast-forward time and request tally", async () => {
    // Advance Hardhat time past voting window
    await network.provider.request({
      method: "evm_increaseTime", params: [DURATION + 10]
    });
    await network.provider.request({ method: "evm_mine" });

    await voting.connect(owner).requestTally(0);
    const p = await voting.proposals(0);
    expect(p.state).to.equal(2); // ProposalState.Closed
    console.log("  ✓ Tally requested. Awaiting Gateway callback...");
    // On local Hardhat with mock Gateway, callback fires automatically.
    // In production the callback arrives in ~2s from KMS.
  });
});

QUESTION 01 / 08
How does castVote() add to either yesCount or noCount without knowing which?
AThe contract decrypts the vote locally using the evaluation key, then uses a plaintext branch
BIt computes an encrypted 1 or 0 per counter using FHE.select(vote, ONE, ZERO) and adds both — so exactly one counter increments by 1, the other by 0, without revealing which
CIt uses FHE.if() to conditionally execute the add operation
DIt stores both possible outcomes and resolves them at tally time
Correct — B. yesAdd = FHE.select(vote, ONE, ZERO) creates an encrypted 1 if YES or encrypted 0 if NO. noAdd = FHE.select(vote, ZERO, ONE) creates the opposite. Adding both to their respective counters means exactly one counter increments — but the contract and observers never know which one.
QUESTION 02 / 08
Why is hasVoted[proposalId][voter] kept as a plaintext bool rather than an encrypted value?
AEncrypted booleans cannot be used in mappings
BIt is cheaper to store plaintext
CWe want to publicly verify whether someone voted (for quorum and double-vote prevention) without revealing how they voted — this is intentional partial transparency
DThe contract needs to revert on double-vote, which requires a plaintext check
Correct — C. Participation is public information — you need to verify quorum and prevent double voting. The sensitive information is the vote direction (YES/NO), which is encrypted. This design separates "who voted" (public) from "how they voted" (private), analogous to a real polling station.
QUESTION 03 / 08
Why must requestTally() call FHE.makePubliclyDecryptable() before requesting Gateway decryption?
AThe Gateway requires a special key to decrypt that is only available after this call
BIt upgrades the handle to a 256-bit format required by the Gateway
CIt signals to the coprocessor to finalize the computation
DThe Gateway's callback will deliver plaintext to the contract, which means the value will be public — makePubliclyDecryptable() registers this intent in the ACL so the KMS knows it's authorized to decrypt for anyone
Correct — D. The ACL needs to authorize public decryption before the Gateway can request it. makePubliclyDecryptable() sets the ACL flag that tells the KMS "anyone is authorized to request decryption of this handle." Without it, the Gateway's decryption request would fail the ACL check.
QUESTION 04 / 08
What attack does the ZK proof in castVote() prevent?
AReplay attacks: copying another voter's encrypted vote from a different proposal or transaction and submitting it as your own
BSybil attacks: a single person voting as multiple addresses
CFront-running: observing votes in the mempool before they are confirmed
DOverflow attacks: submitting a vote that wraps the counter around zero
Correct — A. The ZK proof binds the ciphertext to this specific contract address AND msg.sender. An attacker cannot take Alice's vote from a previous round and re-submit it, nor can they take a vote from a different contract. The proof must be freshly generated for each call.
QUESTION 05 / 08
What type is used for individual votes, and why not euint8?
Aeuint8 — to encode multi-choice votes (0=abstain, 1=yes, 2=no)
Beuint32 — because booleans cannot be used with fromExternal()
Cebool — the most gas-efficient type for binary choices, and it perfectly matches the YES/NO semantics of a binary vote
Deuint64 — to support future weighted voting
Correct — C. ebool is the smallest and cheapest FHE type (1 bit). For a binary YES/NO vote it's semantically perfect. euint8 would work but waste gas encoding 255 unnecessary values. If you need multi-choice or weighted voting, you'd use a larger type and different logic.
QUESTION 06 / 08
What is revealed when VoteCast(proposalId, voter) is emitted?
ANothing — the event is also encrypted
BThat a specific address voted on a specific proposal at a specific time — but not how they voted
CThe vote direction can be inferred from timing patterns
DThe current running tally as of this vote
Correct — B. Solidity events are always plaintext on-chain. The event reveals participation (voter address + proposal + timestamp) but not vote direction. This is an intentional design: participation verification is public, vote content is private.
QUESTION 07 / 08
Can a voter change their vote after casting it?
AYes — they can submit a correction vote before the deadline
BYes — the owner can reset the hasVoted flag
CYes — but only within 5 minutes using the revoteWindow()
DNo — the hasVoted flag prevents double voting. Even if the contract allowed it, subtracting a previous encrypted vote would be complex (you'd need to store each voter's encrypted vote for later subtraction) and is generally not implemented
Correct — D. Once hasVoted is set to true, castVote() always reverts with "Already voted". Supporting vote changes would require storing each voter's previous encrypted vote and using FHE.sub() to remove it — significantly more complex. Most voting systems treat votes as final once cast.
QUESTION 08 / 08
The tallyCallback() receives two uint32 values from the Gateway. What ensures this isn't a fake result injected by an attacker?
AThe onlyGateway modifier verifies msg.sender == Gateway address — only the legitimate Gateway contract can call this function
BThe function checks a cryptographic signature from the KMS nodes
CThe result is compared against an on-chain hash of the expected values
DThe requestId must match a pending request — only the contract knows valid requestIds
Correct — A. The onlyGateway modifier checks msg.sender against the known Gateway contract address set by ZamaConfig. Without it, any address could call tallyCallback(proposalId, 999, 0) and falsify results. The modifier is the single guard that ensures only the legitimate decryption pathway can deliver results.
