Sealed-Bid
Auction

Traditional on-chain auctions are trivially gameable — anyone can see the current highest bid and outbid by one wei at the last second. A sealed-bid auction keeps all bids hidden until close, eliminating sniping and strategic manipulation. Today you build one that finds the winner entirely in FHE without ever revealing losing bids.

Why Sealed-Bid Auctions?

  • No bid sniping — seeing bids in the last seconds and outbidding by minimal amounts is impossible when bids are encrypted
  • No strategic underbidding — knowing others' bids lets you win cheaply; sealed bids force honest valuation
  • No front-running — mempool watchers cannot extract information about bids before they're confirmed
  • Loser privacy — losing bids are never revealed, protecting bidders' valuation strategies
💡
FHEVM Advantage
In a traditional commit-reveal scheme, all bids become public at reveal time. With FHEVM, only the winning bid amount needs to be revealed (via Gateway callback). Losing bids stay encrypted forever — bidders never learn each other's valuations.

Finding the Winner in FHE

The core challenge: finding the maximum among N encrypted bids and identifying the winner, all without revealing any bids. The algorithm is a sequential scan using FHE.gt() and FHE.select():

1

Start with first bidder as current leader

highestBid = bids[0], highestBidder = eaddress(bidders[0]) — both encrypted handles.

2

For each subsequent bidder, compare encrypted bids

ebool isHigher = FHE.gt(bids[i], highestBid) — encrypted comparison. Returns an encrypted bool without revealing either value.

3

Update leader using FHE.select()

highestBid = FHE.select(isHigher, bids[i], highestBid) and highestBidder = FHE.select(isHigher, eaddress(bidders[i]), highestBidder) — atomically update both bid and address.

4

Request decryption of winner only

After scanning all bids, request Gateway decryption of highestBidder and highestBid. Only these two values are revealed — all losing bids stay encrypted forever.

The SealedBidAuction Contract

Storage Layout

Soliditycontracts/SealedBidAuction.sol — storage
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import "@fhevm/solidity/lib/FHE.sol";
import "@fhevm/solidity/config/ZamaConfig.sol";
import "@fhevm/solidity/gateway/GatewayCaller.sol";

contract SealedBidAuction is ZamaEthereumConfig, GatewayCaller {

    enum AuctionState { Bidding, Closed, Settling, Settled }

    // ── Auction config ────────────────────────
    string         public itemDescription;
    uint256        public biddingDeadline;
    uint256        public minBidWei;        // minimum collateral in ETH wei
    address        public immutable owner;
    AuctionState   public state;

    // ── Bid storage ───────────────────────────
    address[]              public  bidders;
    mapping(address => euint64) private bids;          // encrypted bid amounts
    mapping(address => bool)     public  hasBid;
    mapping(address => uint256)  public  deposits;     // ETH collateral

    // ── Result (set after settling) ───────────
    address public winner;
    uint64  public winningBid;       // plaintext only after reveal

    // ── Internal FHE working state ────────────
    euint64   private _highestBid;       // running max (encrypted)
    eaddress  private _highestBidder;   // running winner (encrypted address)

    event BidPlaced(address indexed bidder);          // no amount
    event AuctionClosed(uint256 bidderCount);
    event WinnerRevealed(address indexed winner, uint64 amount);

    constructor(
        string memory item,
        uint256 durationSeconds,
        uint256 _minBidWei
    ) {
        owner            = msg.sender;
        itemDescription  = item;
        biddingDeadline  = block.timestamp + durationSeconds;
        minBidWei        = _minBidWei;
        state            = AuctionState.Bidding;
    }

    modifier onlyOwner() { require(msg.sender == owner, "Not owner"); _; }
}

placeBid() — Submitting an Encrypted Bid

SoliditySealedBidAuction.sol — placeBid
/**
 * @notice Place an encrypted bid with ETH collateral.
 * The bid amount is hidden — collateral ensures commitment.
 * @param encBid  Encrypted bid value (from fhevmjs, euint64)
 * @param proof   ZK proof binding ciphertext to this contract + caller
 */
function placeBid(
    externalEuint64 calldata encBid,
    bytes           calldata proof
) external payable {
    require(state == AuctionState.Bidding,    "Auction not open");
    require(block.timestamp < biddingDeadline, "Bidding closed");
    require(!hasBid[msg.sender],               "Already bid");
    require(msg.value >= minBidWei,            "Insufficient collateral");

    // Validate ZK proof and get encrypted bid handle
    euint64 bidAmount = FHE.fromExternal(encBid, proof);

    // Store encrypted bid and grant ACL
    bids[msg.sender] = bidAmount;
    FHE.allowThis(bids[msg.sender]);
    FHE.allow(bids[msg.sender], msg.sender);  // bidder can verify own bid

    deposits[msg.sender] = msg.value;
    hasBid[msg.sender]   = true;
    bidders.push(msg.sender);

    emit BidPlaced(msg.sender);  // address only, no amount
}

closeAuction() — Find the Winner in FHE

SoliditySealedBidAuction.sol — closeAuction
/**
 * @notice Close bidding and find the highest bidder using FHE comparisons.
 * Scans all bids with a linear encrypted max search, then requests
 * Gateway decryption of winner identity and amount only.
 */
function closeAuction() external onlyOwner {
    require(state == AuctionState.Bidding,    "Not bidding");
    require(block.timestamp >= biddingDeadline, "Deadline not passed");
    require(bidders.length > 0,               "No bidders");

    state = AuctionState.Closed;

    // ── Find max bid using linear FHE scan ─────
    // Initialize with first bidder
    _highestBid    = bids[bidders[0]];
    _highestBidder = FHE.asEaddress(bidders[0]);

    FHE.allowThis(_highestBid);
    FHE.allowThis(_highestBidder);

    // Compare remaining bidders
    for (uint256 i = 1; i < bidders.length; i++) {
        address challenger = bidders[i];
        ebool   isHigher    = FHE.gt(bids[challenger], _highestBid);

        // If challenger bid is higher, update both bid and bidder address
        _highestBid    = FHE.select(isHigher, bids[challenger], _highestBid);
        _highestBidder = FHE.select(isHigher,
            FHE.asEaddress(challenger),
            _highestBidder
        );

        FHE.allowThis(_highestBid);
        FHE.allowThis(_highestBidder);
    }

    // ── Request decryption of winner info only ─
    FHE.makePubliclyDecryptable(_highestBid);
    FHE.makePubliclyDecryptable(_highestBidder);

    uint256[] memory handles = new uint256[](2);
    handles[0] = euint64.unwrap(_highestBid);
    handles[1] = eaddress.unwrap(_highestBidder);

    Gateway.requestDecryption(
        handles,
        this.winnerCallback.selector,
        0,
        block.timestamp + 1 hours,
        false
    );

    state = AuctionState.Settling;
    emit AuctionClosed(bidders.length);
}

winnerCallback() — Settle the Auction

SoliditySealedBidAuction.sol — winnerCallback
/// @dev Gateway calls this with decrypted winner address and bid amount
function winnerCallback(
    uint256 /* requestId */,
    uint64  winningAmount,
    address winnerAddr
) external onlyGateway {
    winner      = winnerAddr;
    winningBid  = winningAmount;
    state       = AuctionState.Settled;

    emit WinnerRevealed(winnerAddr, winningAmount);
}

/// @notice Anyone can verify the winner and winning bid post-auction
function getResult() external view returns(address, uint64) {
    require(state == AuctionState.Settled, "Not settled");
    return (winner, winningBid);
}

claimRefund() — Losers Get Their ETH Back

SoliditySealedBidAuction.sol — refund
/**
 * @notice Losing bidders reclaim their full ETH collateral.
 * Winner's collateral is retained as payment (simplification —
 * production contracts would handle payment separately).
 */
function claimRefund() external {
    require(state == AuctionState.Settled, "Not settled");
    require(msg.sender != winner,           "Winner cannot refund");
    require(hasBid[msg.sender],             "No bid placed");

    uint256 amount = deposits[msg.sender];
    require(amount > 0,                   "Already refunded");

    deposits[msg.sender] = 0;                   // prevent re-entrancy
    (bool ok,) = msg.sender.call{value: amount}("");
    require(ok, "ETH transfer failed");
}
⚠
Collateral vs. Payment
This example uses ETH collateral as a commitment mechanism. In production, you'd separate bid commitment from actual payment — the winner pays the winning amount separately, and everyone gets collateral back. The collateral just ensures bidders are serious and prevents spam bids.

The Encrypted Maximum Pattern

Finding a maximum among N encrypted values is a fundamental FHEVM pattern you'll reuse across many contracts. It generalizes to any comparison-based selection:

SolidityGeneric encrypted max scan
/**
 * Encrypted linear max scan — O(N) FHE comparisons.
 * Selects both the max value AND its associated metadata (here: address)
 * using FHE.select() to keep both synchronized.
 *
 * Works for any type where FHE.gt() is defined: euint8, euint16, euint32, euint64
 */
function _findMax(
    address[] storage participants,
    mapping(address => euint64) storage values
) internal returns (euint64 maxVal, eaddress maxHolder) {
    maxVal    = values[participants[0]];
    maxHolder = FHE.asEaddress(participants[0]);
    FHE.allowThis(maxVal);
    FHE.allowThis(maxHolder);

    for (uint256 i = 1; i < participants.length; i++) {
        ebool isBetter = FHE.gt(values[participants[i]], maxVal);

        // CRITICAL: Update BOTH value and metadata atomically via select
        // This keeps them synchronized — they always refer to the same participant
        maxVal    = FHE.select(isBetter, values[participants[i]], maxVal);
        maxHolder = FHE.select(isBetter, FHE.asEaddress(participants[i]), maxHolder);

        FHE.allowThis(maxVal);
        FHE.allowThis(maxHolder);
    }
}

// Gas note: Each FHE.gt() + 2×FHE.select() costs ~3× the baseline FHE op cost.
// For N bidders: O(N) Gateway requests, each taking ~2s off-chain.
// For large auctions (N>50) consider batched or tree-based approaches.

Deposit Strategy & Anti-Spam

💡
Why ETH Collateral Is Essential
Without collateral, anyone can spam fake bids at zero cost. The encrypted bid amount doesn't match their collateral — but since bids are sealed, the auction can't verify amounts before close. Requiring a minBidWei deposit ensures every bidder has skin in the game. The deposit should match or exceed a reasonable floor price for the item.

TypeScripttest/SealedBidAuction.test.ts
import { ethers, network } from "hardhat";
import { expect } from "chai";
import { getFhevmInstance } from "./helpers";
import { ethers as e } from "ethers";

describe("SealedBidAuction", () => {
  let auction: any;
  let owner: any, alice: any, bob: any, carol: any;
  const DURATION  = 3600;                        // 1 hour
  const MIN_BID   = e.parseEther("0.01");       // 0.01 ETH collateral

  before(async () => {
    [owner, alice, bob, carol] = await ethers.getSigners();
    const F = await ethers.getContractFactory("SealedBidAuction");
    auction = await F.deploy("Vintage Crypto Punk #001", DURATION, MIN_BID);
    await auction.waitForDeployment();
    console.log("  Auction:", await auction.getAddress());
  });

  it("alice bids 500 (encrypted)", async () => {
    const instance = await getFhevmInstance();
    const addr     = await auction.getAddress();

    const input = instance.createEncryptedInput(addr, alice.address);
    input.add64(500);
    const { handles, inputProof } = await input.encrypt();

    await auction.connect(alice).placeBid(handles[0], inputProof, { value: MIN_BID });
    expect(await auction.hasBid(alice.address)).to.be.true;
    console.log("  ✓ Alice bid placed (amount hidden)");
  });

  it("bob bids 750 (encrypted) — highest bid", async () => {
    const instance = await getFhevmInstance();
    const addr     = await auction.getAddress();
    const input    = instance.createEncryptedInput(addr, bob.address);
    input.add64(750);
    const { handles, inputProof } = await input.encrypt();
    await auction.connect(bob).placeBid(handles[0], inputProof, { value: MIN_BID });
    console.log("  ✓ Bob bid placed (amount hidden)");
  });

  it("carol bids 300 (lowest)", async () => {
    const instance = await getFhevmInstance();
    const addr     = await auction.getAddress();
    const input    = instance.createEncryptedInput(addr, carol.address);
    input.add64(300);
    const { handles, inputProof } = await input.encrypt();
    await auction.connect(carol).placeBid(handles[0], inputProof, { value: MIN_BID });
    expect(await auction.bidders(2)).to.equal(carol.address);
    console.log("  ✓ 3 bids placed — all hidden from each other");
  });

  it("cannot bid twice", async () => {
    const instance = await getFhevmInstance();
    const addr     = await auction.getAddress();
    const input    = instance.createEncryptedInput(addr, alice.address);
    input.add64(999);
    const { handles, inputProof } = await input.encrypt();
    await expect(
      auction.connect(alice).placeBid(handles[0], inputProof, { value: MIN_BID })
    ).to.be.revertedWith("Already bid");
  });

  it("close auction and find winner (bob = 750)", async () => {
    await network.provider.request({
      method: "evm_increaseTime", params: [DURATION + 10]
    });
    await network.provider.request({ method: "evm_mine" });

    await auction.connect(owner).closeAuction();
    // On local Hardhat the Gateway mock fires the callback automatically
    // In production: wait ~2s for KMS to respond
    console.log("  ✓ closeAuction() called. Awaiting settlement...");
  });

  it("alice and carol can claim refunds after settlement", async () => {
    // (After Gateway callback fires and state = Settled)
    const [w] = await auction.getResult();
    expect(w).to.equal(bob.address);  // bob wins with 750

    const aliceBefore = await ethers.provider.getBalance(alice.address);
    await auction.connect(alice).claimRefund();
    const aliceAfter  = await ethers.provider.getBalance(alice.address);
    expect(aliceAfter).to.be.greaterThan(aliceBefore);
    console.log("  ✓ Alice refunded. Carol's refund follows same pattern.");
  });
});

QUESTION 01 / 08
In the FHE max scan, why is it critical to update both _highestBid and _highestBidder using FHE.select() with the same condition?
ATo reduce gas by batching two selects into one FHE operation
BThe coprocessor requires paired select calls for eaddress types
CTo keep bid amount and bidder identity synchronized — if you update one without the other using the same condition, they'd refer to different participants, producing an incorrect result
DFHE.gt() returns a handle that can only be consumed once
Correct — C. The max amount and the identity of who submitted it must stay synchronized. If you updated highestBid to challenger's amount but forgot to update highestBidder, the contract would think the old winner won with the challenger's higher amount — a completely wrong result. Both must update atomically with the same encrypted condition.
QUESTION 02 / 08
What information is revealed when the auction settles?
AOnly the winner's address and winning bid amount — all losing bids stay encrypted and are never revealed
BAll bids are revealed, but only the winner's identity is kept private
CAll bid amounts are revealed, but bidder identities remain hidden
DNothing — the auction is fully private even after settlement
Correct — A. Only the winner's address and winning amount are decrypted via the Gateway callback and stored as plaintext. All other bids remain as encrypted handles on-chain — their amounts are never revealed, protecting bidders' valuation strategies.
QUESTION 03 / 08
Why does placeBid() require an ETH collateral deposit?
AThe KMS charges ETH for decryption services
BTo verify the bidder has sufficient funds to cover their bid
CETH is needed to pay for coprocessor computation
DWithout collateral, anyone could spam free bids — since bid amounts are encrypted and can't be verified, the deposit is the only anti-spam mechanism that proves commitment
Correct — D. Since bid amounts are encrypted, the contract can't verify that a bidder actually has the funds they're claiming to bid. The ETH deposit ensures every bid has real economic cost, preventing spam and ensuring the winning bidder has at least some collateral committed.
QUESTION 04 / 08
What is the time complexity of the closeAuction() FHE scan over N bidders?
AO(log N) — it uses a tree-based FHE comparison structure
BO(N) — one FHE comparison per bidder in a linear scan
CO(N²) — each bid is compared against all other bids
DO(1) — the coprocessor finds the max in a single parallel operation
Correct — B. The loop iterates once per bidder after the first, performing one FHE.gt() and two FHE.select() calls per iteration — O(N) total FHE operations. For large auctions this can become expensive; a tree-based reduction would be O(N log N) round-trips but could reduce sequential gas costs.
QUESTION 05 / 08
Why is deposits[msg.sender] = 0 set before transferring ETH in claimRefund()?
ATo emit an event before the transfer for gas ordering
BThe EVM requires state changes before external calls in the same frame
CRe-entrancy protection — if the recipient is a malicious contract that calls claimRefund() again during ETH receipt, the balance is already zero so the second call gets nothing
DSolidity optimizes storage writes that precede external calls
Correct — C. The checks-effects-interactions pattern: first check (require), then effects (set balance to 0), then interactions (transfer ETH). If you sent ETH before zeroing the balance, a malicious recipient contract could re-enter claimRefund() and drain multiple times. Zeroing first is the standard re-entrancy guard.
QUESTION 06 / 08
How does a sealed-bid auction prevent last-second bid sniping?
ABy using a commit-reveal scheme that requires a 24-hour reveal window
BBy only accepting bids from pre-registered addresses
CBy randomizing the actual auction close time
DBids are encrypted — no bidder can see others' bids during the auction. Without knowing the current highest bid, there's no information advantage to bidding late; every bidder must bid their true maximum from the start
Correct — D. Sniping requires knowing the current highest bid to outbid by one unit. With encrypted bids, this information is unavailable — you can't see what to outbid. Bidding early vs late provides no strategic advantage, which means bidders reveal their true valuations rather than gaming the timing.
QUESTION 07 / 08
What is the role of eaddress type in the auction?
ATo encrypt the winner's identity during the max scan so no one knows who's leading until the Gateway reveals the result
BTo store bidder addresses more gas-efficiently than address type
CTo prevent bidder addresses from appearing in block explorers
Deaddress is required for FHE.select() to work with address types
Correct — A. During the linear max scan, _highestBidder is an encrypted eaddress. This means even as the scan progresses, no one can observe which address is currently "winning" — the identity is only revealed when the Gateway decrypts and delivers it to the winnerCallback. Without this, observers could watch which address gets updated and infer who's leading.
QUESTION 08 / 08
What happens if two bidders submit the exact same encrypted bid amount?
ABoth are declared co-winners and must split the prize
BThe earlier bidder wins — FHE.gt() returns false for equal values (not strictly greater), so the current leader is kept when tied
CThe contract reverts because ties are not handled
DA random tiebreaker is selected using block.prevrandao
Correct — B. FHE.gt(challenger, current) returns false when they're equal (not strictly greater). FHE.select(false, challenger, current) keeps the current leader. So in a tie, the bidder who was already the leader (earlier in the array, which reflects earlier submission order) wins. This is a deterministic tie-breaking rule implicit in the algorithm.
