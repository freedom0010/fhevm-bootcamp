FHEVM Vulnerability Taxonomy

Every FHEVM bug falls into one of five severity classes. The table below maps severity, root cause, detection method, and the business impact of exploitation.

⚠
The Two Catastrophic Anti-Patterns
These two patterns are critical severity because they completely defeat FHE encryption:

1. On-chain decrypt: FHE.decrypt(secret) in a transaction publishes the plaintext in calldata, accessible to every node and block explorer permanently.

2. Encrypted branch oracle: if (FHE.eq(balance, target)) — if the transaction reverts when false and succeeds when true, an attacker binary-searches the secret. A 64-bit value is recoverable in ≤64 transactions.

Critical Severity — Examples

CRITICAL FHEVM-001 Direct On-Chain Decryption
Calling FHE.decrypt() in a transaction or view function emits the plaintext into the EVM execution trace. Block explorers, archive nodes, and anyone replaying the transaction can read the value.
❌ Vulnerable
function getBalance()
  external view returns (uint64) {
  // CRITICAL: decrypts on-chain
  // plaintext in calldata!
  return FHE.decrypt(
    _balance[msg.sender]
  );
}
✓ Fixed Pattern
function getBalance()
  external view returns (euint64) {
  // Return encrypted handle
  // Client decrypts via re-enc
  require(FHE.isSenderAllowed(
    _balance[msg.sender]
  ), "Not authorized");
  return _balance[msg.sender];
}
Remediation
// Off-chain decryption via fhevmjs (correct pattern):
// 1. Call getBalance() — returns euint64 handle
// 2. instance.createEIP712(pubKey, contractAddr) → signature
// 3. instance.reencrypt(handle, privKey, pubKey, sig, contract, user)
// 4. instance.decrypt(contract, reencrypted) → plaintext locally
// Plaintext NEVER touches the blockchain
CRITICAL FHEVM-002 Encrypted Branch Oracle (Revert Leak)
Using an ebool in a conditional statement (if/require) leaks its value via the transaction success/failure. An attacker calls the function repeatedly with different test values to binary-search the secret.
❌ Vulnerable
function checkBalance(
  uint64 guess
) external {
  ebool eq = FHE.eq(
    _balance[msg.sender],
    FHE.asEuint64(guess)
  );
  // CRITICAL: revert reveals ebool!
  require(
    FHE.decrypt(eq),
    "Wrong guess"
  );
}
✓ Fixed Pattern
function getEncryptedBalance()
  external view returns (euint64) {
  // Never compare plaintext guesses
  // against encrypted values on-chain
  require(FHE.isSenderAllowed(
    _balance[msg.sender]
  ));
  return _balance[msg.sender];
  // Client does comparison locally
}
Attack Vector (64-bit secret recovery)
// Attacker script: binary search to find secret value
// Total calls needed: log₂(2^64) = 64 transactions
lo = 0n; hi = 18446744073709551615n;  // uint64 max
while (lo < hi) {
  mid = (lo + hi) / 2n;
  try { await contract.checkBalance(mid);    lo = mid + 1n; }
  catch {                                          hi = mid;     }
}
// After 64 calls: lo === secret value

High Severity — Examples

HIGH FHEVM-003 Missing allowThis() After FHE Operation
Every FHE operation that produces a new handle creates a handle with zero ACL entries. If the contract does not immediately call FHE.allowThis(), it permanently loses access to the result — DoS on all subsequent operations.
❌ Vulnerable
function deposit(
  externalEuint64 calldata enc,
  bytes           calldata prf
) external {
  euint64 amt = FHE.fromExternal(enc, prf);
  // ❌ new handle — contract has NO access!
  _bal[msg.sender] = FHE.add(
    _bal[msg.sender], amt
  );
  // Next call: "ACL: not allowed"
}
✓ Fixed
function deposit(
  externalEuint64 calldata enc,
  bytes           calldata prf
) external {
  euint64 amt = FHE.fromExternal(enc, prf);
  euint64 newBal = FHE.add(
    _bal[msg.sender], amt
  );
  // ✅ grant access to new handle
  FHE.allowThis(newBal);
  FHE.allow(newBal, msg.sender);
  _bal[msg.sender] = newBal;
}
Detection Rule
// Taint rule: every assignment of a new euint variable must be
// followed (in the same function body) by allowThis() on that variable.
// Slither custom detector pseudocode:
for node in cfg:
  if node.is_fhe_op():        // FHE.add/sub/mul/select/fromExternal
    result_var = node.lhs
    if not result_var.has_downstream(FHE.allowThis):
      report("FHEVM-003: missing allowThis on {result_var}")
HIGH FHEVM-004 Gateway Callback Without onlyGateway
A callback function that settles an auction, vote, or liquidation — without the onlyGateway modifier — allows any address to invoke it with a crafted plaintext value, completely bypassing FHE decryption.
❌ Vulnerable
// Anyone can call with fake winner!
function settleAuction(
  uint256 reqId,
  address winner,
  uint64  amount
) external {
  // ❌ No modifier — attacker calls
  // this directly with fake values
  _winner = winner;
  _amount = amount;
  payable(winner).transfer(
    address(this).balance
  );
}
✓ Fixed
// Only Gateway contract can call
function settleAuction(
  uint256 reqId,
  address winner,
  uint64  amount
// ✅ modifier enforces Gateway addr
) external onlyGateway {
  _winner = winner;
  _amount = amount;
  payable(winner).transfer(
    address(this).balance
  );
}
HIGH FHEVM-005 Unauthorized makePubliclyDecryptable()
FHE.makePubliclyDecryptable() permanently removes privacy from a ciphertext. If any address can call a function that invokes it, they can permanently reveal any encrypted value in the contract.
❌ Vulnerable
// Anyone can expose any salary!
function revealSalary(
  address employee
) external {
  // ❌ No access control
  FHE.makePubliclyDecryptable(
    salaries[employee]
  );
  Gateway.requestDecryption(
    salaries[employee], ...
  );
}
✓ Fixed
function revealSalary(
  address employee
) external {
  // ✅ Only the employee themselves
  // can reveal their own salary
  require(
    msg.sender == employee,
    "Not your salary"
  );
  FHE.makePubliclyDecryptable(
    salaries[employee]
  );
  Gateway.requestDecryption(...);
}

Medium and Low Severity

MEDIUM FHEVM-006 Uninitialized Encrypted Variable
A euint64 storage variable defaults to zero — a valid-looking handle that wraps the value 0. Any FHE operation on this uninitialized value silently propagates 0 through the computation, corrupting results.
❌ Vulnerable
contract Counter {
  euint64 private count;
  // ❌ count is a zero handle
  // (not the same as euint64(0))

  function increment() external {
    count = FHE.add(
      count,           // uninitialized!
      FHE.asEuint64(1)
    );
    FHE.allowThis(count);
  }
}
✓ Fixed
contract Counter {
  euint64 private count;
  bool    private initialized;

  constructor() {
    // ✅ explicit initialization
    count = FHE.asEuint64(0);
    FHE.allowThis(count);
    initialized = true;
  }

  function increment() external {
    require(initialized);
    count = FHE.add(count, FHE.asEuint64(1));
    FHE.allowThis(count);
  }
}
MEDIUM FHEVM-007 Encrypted Arithmetic Overflow / Wraparound
FHE arithmetic wraps silently on overflow without reverting. An attacker who can add values to an euint8 balance can wrap it from 255 to 0, or manipulate a small-type accumulator to arbitrary values.
❌ Vulnerable
euint8 private score;  // max 255

function addScore(
  externalEuint8 calldata enc,
  bytes          calldata prf
) external {
  euint8 pts = FHE.fromExternal(enc, prf);
  // ❌ no overflow guard
  // score + pts wraps silently at 256
  score = FHE.add(score, pts);
  FHE.allowThis(score);
}
✓ Fixed — Saturating Add
euint8 private score;

function addScore(
  externalEuint8 calldata enc,
  bytes          calldata prf
) external {
  euint8 pts = FHE.fromExternal(enc, prf);
  euint8 sum = FHE.add(score, pts);
  // ✅ cap at 255 using FHE.select
  // if sum < score: overflow occurred
  ebool  overflow = FHE.lt(sum, score);
  euint8 max255   = FHE.asEuint8(255);
  score = FHE.select(overflow, max255, sum);
  FHE.allowThis(score);
}

Audit Process

1
Scope & Dependency Mapping
List all contracts, identify which import FHE.sol and GatewayCaller.sol. Map every function that: accepts externalEuintX parameters, calls FHE operations, calls Gateway, emits events containing encrypted handles, or calls external contracts with euint arguments. This is your attack surface.
2
Static Analysis Pass
Run automated grep rules and Slither custom detectors (see below) to catch FHEVM-001 through FHEVM-007. This pass catches ~70% of issues mechanically — false positive rate is low because the patterns are very specific.
3
Manual Review — Handle Lifecycle
Trace every encrypted variable from creation (constructor / fromExternal) through every write path to every read path. Verify allowThis() and allow() are called correctly at every point where the handle changes. Use the taint graph: every handle must have an unbroken chain of ACL grants.
4
Access Control Audit
For every function calling makePubliclyDecryptable() or requestDecryption(): verify caller restrictions are correct and minimal. For every callback function: verify the onlyGateway modifier is present and the modifier correctly checks msg.sender == GATEWAY_ADDRESS.
5
Fuzz Testing
Run the invariant test suite (from Day 10) with Foundry's fuzz runner against 10,000+ random input sequences. Key invariants: sum of encrypted balances == totalSupply, all handles have allowThis(), no handle is zero after initialization, Gateway callback can only be triggered once per request ID.
6
Report & Remediation
Produce findings grouped by severity. For each finding: FHEVM vulnerability class, affected function, proof-of-concept (exploit code or test), and the recommended fix. Require developer fixes with re-audit of changed functions before deployment sign-off.

Static Analysis — Grep Rules

Bashaudit/static-scan.sh
#!/bin/bash
# FHEVM Static Analysis Script
# Run from project root: bash audit/static-scan.sh contracts/

TARGET=${1:-contracts/}
FINDINGS=0

check() {
  local SEVERITY=$1 RULE=$2 PATTERN=$3 MSG=$4
  local RESULTS=$(grep -rn "$PATTERN" "$TARGET" --include="*.sol" 2>/dev/null)
  if [ -n "$RESULTS" ]; then
    echo ""
    echo "[$SEVERITY] $RULE: $MSG"
    echo "$RESULTS" | while read line; do echo "  $line"; done
    FINDINGS=$((FINDINGS + 1))
  fi
}

echo "=== FHEVM Security Scan ==="
echo "Target: $TARGET"
echo ""

# CRITICAL checks
check "CRITICAL" "FHEVM-001" \
  'FHE\.decrypt(' \
  "On-chain decryption detected — plaintext exposed in calldata"

check "CRITICAL" "FHEVM-002a" \
  'if.*ebool\|if.*FHE\.eq\|if.*FHE\.lt\|if.*FHE\.gt\|if.*FHE\.lte\|if.*FHE\.gte' \
  "Encrypted bool used in branch condition — revert oracle vulnerability"

check "CRITICAL" "FHEVM-002b" \
  'require.*FHE\.\|require.*ebool' \
  "Encrypted value used in require — revert oracle vulnerability"

# HIGH checks
check "HIGH" "FHEVM-004" \
  'function.*callback.*external\b' \
  "External callback function — verify onlyGateway modifier is present"

check "HIGH" "FHEVM-005" \
  'makePubliclyDecryptable' \
  "makePubliclyDecryptable usage — verify access control on caller"

check "HIGH" "FHEVM-008" \
  'allowTransient\|allowTransient' \
  "Verify allowTransient() is called BEFORE every cross-contract call with euint arg"

# MEDIUM checks
check "MEDIUM" "FHEVM-006" \
  'euint[0-9]* private [a-zA-Z]' \
  "euint storage variable — verify initialized in constructor"

check "INFO" "FHEVM-009" \
  'emit.*[Tt]ransfer\|emit.*[Bb]alance\|emit.*[Aa]mount' \
  "Event may emit amount metadata — verify no correlation with encrypted values"

echo ""
echo "=== Scan Complete: $FINDINGS rule(s) triggered ==="
echo "NOTE: This scan detects patterns, not logic errors."
echo "All triggered rules require manual verification."

Manual Review — Handle Lifecycle Tracing

TypeScriptaudit/handle-trace.ts — ACL verification in tests
import { ethers } from "hardhat";

const ACL_ABI = [
  "function isAllowed(bytes32 handle, address account) view returns (bool)"
];

/**
 * Verify that a handle has correct ACL grants after an operation.
 * Call this in audit tests after every state-changing function.
 *
 * @param handle        The euint handle to check (as bigint)
 * @param contractAddr  The contract that should have allowThis()
 * @param authorizedUsers  Addresses that should have allow()
 * @param unauthorizedUsers  Addresses that should NOT have access
 */
export async function auditHandleACL(
  handle:             bigint,
  contractAddr:       string,
  authorizedUsers:    string[],
  unauthorizedUsers:  string[]
) {
  const acl = new ethers.Contract(
    "0x339EcE85B9E11a3A3AA557582784a15d7F82AAf2",
    ACL_ABI,
    ethers.provider
  );
  const failures: string[] = [];

  // Contract must always have allowThis()
  if (!(await acl.isAllowed(handle, contractAddr))) {
    failures.push(`FAIL: contract ${contractAddr} missing allowThis()`);
  }

  // Authorized users must have access
  for (const user of authorizedUsers) {
    if (!(await acl.isAllowed(handle, user))) {
      failures.push(`FAIL: authorized user ${user} missing allow()`);
    }
  }

  // Unauthorized users must NOT have access
  for (const addr of unauthorizedUsers) {
    if (await acl.isAllowed(handle, addr)) {
      failures.push(`FAIL: unauthorized address ${addr} has access`);
    }
  }

  if (failures.length > 0) {
    console.error("\n[AUDIT FAILURE] Handle ACL violations:");
    failures.forEach(f => console.error(" ", f));
    throw new Error(`${failures.length} ACL violation(s) found`);
  }

  console.log(`[AUDIT OK] Handle ACL correct — ${authorizedUsers.length} authorized, ${unauthorizedUsers.length} excluded`);
}

Fuzz Testing — FHEVM Invariants

TypeScriptaudit/fuzz.invariants.test.ts
import { ethers } from "hardhat";

/**
 * Fuzz test: randomly sequence deposits + transfers + withdrawals
 * and verify FHEVM-specific invariants after every operation.
 *
 * Run with: HARDHAT_FHEVM_MOCK=true npx hardhat test audit/fuzz.invariants.test.ts
 */
describe("FHEVM Invariant Fuzz — ConfidentialERC20", () => {
  const RUNS = 500;  // increase for deeper coverage

  it(`survives ${RUNS} random operations with all invariants held`, async () => {
    const [owner, alice, bob, carol] = await ethers.getSigners();
    const signers = [alice, bob, carol];

    const F = await ethers.getContractFactory("ConfidentialERC20");
    const token = await F.deploy("FuzzToken", "FZZ");
    const addr   = await token.getAddress();

    // Seed balances
    for (const s of signers) await token.mint(s.address, 1000n);

    let totalMinted = 3000n;

    for (let i = 0; i < RUNS; i++) {
      // Pick random operation: 0=mint, 1=transfer, 2=burn
      const op   = Math.floor(Math.random() * 3);
      const from = signers[Math.floor(Math.random() * signers.length)];
      const to   = signers[Math.floor(Math.random() * signers.length)];
      const amt  = BigInt(Math.floor(Math.random() * 100));

      try {
        if (op === 0) {
          await token.connect(owner).mint(from.address, amt);
          totalMinted += amt;
        } else if (op === 1) {
          const { handles: h, inputProof: p } =
            await encUint64(amt, addr, from.address);
          await token.connect(from).transfer(to.address, h[0], p);
        }
      } catch {} // silent failures OK — cap-not-revert pattern

      // ─── INVARIANT CHECKS after every operation ───
      const supply = await token.totalSupply();
      expect(supply).to.equal(totalMinted, `Run ${i}: totalSupply mismatch`);

      for (const s of signers) {
        const handle = await token.connect(s).balanceOf(s.address);
        // Verify contract ACL is maintained
        const ok = await acl.isAllowed(handle, addr);
        expect(ok).to.be.true, `Run ${i}: ${s.address} balance handle lost allowThis`;
      }
    }
    console.log(`Fuzz complete: ${RUNS} operations, all invariants held`);
  });
});

30-Item Audit Checklist

Work through every item before signing off on a FHEVM contract. Click each item to mark it complete.

CRITICAL — Privacy Violations
No FHE.decrypt() call exists in any transaction-executing function (only off-chain via fhevmjs)
No ebool or FHE comparison result is used as an if / require / ternary condition
No FHE result is directly returned as plaintext to the caller
HIGH — ACL Correctness
Every FHE.add / sub / mul / div / select / fromExternal result has FHE.allowThis() in the same function
Every user-facing encrypted storage variable has FHE.allow(handle, user) after every write path
Every cross-contract call passing a euint argument is preceded by FHE.allowTransient(handle, contractB)
Persistent cross-contract handle sharing uses FHE.allow(handle, contractB) not allowTransient
HIGH — Gateway Security
Every Gateway callback function has the onlyGateway modifier
The onlyGateway modifier checks msg.sender == GATEWAY_ADDRESS (not just a role flag)
Every callback stores and validates the requestId to prevent double-execution
requestId → entity mapping is cleared after callback to prevent replay
HIGH — Public Reveal Control
Every function calling makePubliclyDecryptable() has proper access control (owner-only or user-only)
makePubliclyDecryptable() is only called on handles that legitimately need public decryption (aggregates, not individual positions)
There is no path where an unauthorized user can trigger public reveal of another user's data
MEDIUM — Arithmetic Safety
All euint8 / euint16 arithmetic has overflow guards (FHE.select saturating pattern)
All subtraction has underflow guards (FHE.select(gte(a,b), FHE.sub(a,b), zero))
All euint64 / euint128 multiplications won't overflow given domain constraints
No FHE.div() used in hot paths (high gas cost — verify alternatives were considered)
MEDIUM — Initialization
All euint storage variables are explicitly initialized (constructor or first-use guard)
No FHE operation is performed on a handle that could be zero (uninitialized)
Proxy contracts properly reinitialize encrypted storage after upgrades
MEDIUM — Input Validation
FHE.fromExternal(enc, proof) is used for all user-supplied encrypted inputs (not raw handle casting)
No proof is cached and reused across different contract addresses or callers
Type sizes are appropriate (don't use euint128 where euint32 suffices — unnecessary gas cost)
LOW — Information Leakage
Events do not emit correlated metadata that would allow deanonymization of encrypted amounts
Function call patterns (which functions are called, when, by whom) do not leak sensitive information
Gas usage differences between branches do not create timing side channels
TESTING
Unit test suite runs in both mock mode and real-FHE mode
Invariant fuzz test runs ≥500 random operation sequences
ACL invariant is verified after every state-changing operation in integration tests
Static analysis scan (FHEVM-001 through FHEVM-009) passes with zero findings
Progress: 0 / 30 items complete

Day 16 Quiz — Security Audit Framework
8 questions · select one answer each, then submit
QUESTION 01 / 08
Why is using an ebool in an if statement classified as CRITICAL severity — even though no explicit FHE.decrypt() is called?
ABecause if (ebool) automatically triggers on-chain decryption internally
BThe transaction revert/success itself encodes the boolean value — an attacker binary-searches any encrypted value by calling the function repeatedly with different test values, recovering a 64-bit secret in just 64 calls
Cebool types cannot be used in conditionals due to Solidity type restrictions
DIt creates a gas difference that leaks the bit width of the encrypted value
Correct — B. This is the revert oracle attack. When if (FHE.eq(secret, guess)) is used, a false guess reverts (or takes a different code path) while a true guess succeeds. The attacker observes the outcome (revert vs success) as a 1-bit oracle. With binary search on a 64-bit value space, they recover the secret in exactly 64 transactions.
QUESTION 02 / 08
What is the correct way to return an encrypted value to a user for off-chain reading?
ACall FHE.decrypt(handle) and return the plaintext uint64
BEmit the handle in an event so the user can find it in logs
CStore it in a public mapping so the user can read it directly
DReturn the euint64 handle from a view function (after verifying ACL with FHE.isSenderAllowed()), then the client uses fhevmjs re-encryption to decrypt locally — plaintext never touches the chain
Correct — D. The correct flow: 1) contract returns the euint handle, 2) client calls instance.createEIP712() to create a re-encryption request signed by the user, 3) client calls instance.reencrypt() which asks the KMS to re-encrypt the ciphertext under the client's ephemeral public key, 4) client decrypts locally. The plaintext is only ever on the client device.
QUESTION 03 / 08
A contract has a callback function settleAuction(uint256 reqId, address winner) that transfers ETH to the winner. What is the severity if it lacks onlyGateway?
AHIGH — any address can call settleAuction with a crafted winner address, draining the contract's ETH balance without any valid decryption having occurred
BMEDIUM — only the owner can call it in practice since only the owner initiates the auction
CLOW — the Gateway will still call it correctly regardless
DCRITICAL — it also decrypts the value on-chain
Correct — A. Without onlyGateway, any address can call settleAuction(reqId, attackerAddress) directly, bypassing the entire FHE decryption process. The attacker sets themselves as the winner and receives all the ETH. This is a complete funds drain vulnerability. The Gateway modifier is the only thing separating "FHE-protected settlement" from "free ETH for anyone."
QUESTION 04 / 08
Why is an uninitialized euint64 storage variable a MEDIUM severity issue rather than just an edge case?
ABecause uninitialized variables always revert when used in FHE operations
BBecause accessing an uninitialized variable depletes the contract's gas allowance
CA zero handle represents an uninitialized state, not the value zero — FHE arithmetic on it produces silently corrupted results without any error or revert. The bug is invisible in tests that don't check the decrypted value.
DIt causes the constructor to fail silently, leaving the contract in a broken state
Correct — C. The default value of a euint64 storage variable is the zero handle — which is distinct from FHE.asEuint64(0). Operations on the zero handle may produce nonsense values or silently wrap. Unlike a plaintext uint that defaults to 0 and is usable, the zero handle is genuinely uninitialized and must be explicitly set with FHE.asEuint64(initialValue) before use.
QUESTION 05 / 08
What is the purpose of storing the requestId → entityId mapping in a Gateway callback setup, and what bug does NOT storing it create?
AIt is for gas optimization — storing it avoids re-computation in the callback
BIt prevents duplicate requests being sent to the Gateway
CIt allows the callback to be retried if it fails the first time
DThe callback needs to know which auction/vote/proposal the decrypted value belongs to. Without the mapping, the callback either always updates the wrong entity or requires an unsafe assumption that there's only one active request at a time
Correct — D. requestDecryption() returns a uint256 requestId. The callback receives this requestId as its first parameter. If you don't store reqId→auctionId (or proposalId, etc.), the callback has no way to know which entity to update. The bug: if multiple auctions are running concurrently, callbacks may settle the wrong auction, or all callbacks may overwrite a single shared state variable.
QUESTION 06 / 08
How does the static analysis script detect the encrypted branch oracle vulnerability (FHEVM-002)?
AIt compiles the contract and checks the bytecode for conditional jumps
BIt greps the Solidity source for if/require expressions whose argument contains an ebool type or a call to FHE.eq/lt/gt/lte/gte
CIt runs the contract with test inputs and monitors which branches are taken
DIt checks that every ebool variable is only used as a FHE.select() argument
Correct — B. The static scan uses regex patterns to find if.*ebool, if.*FHE.eq, require.*FHE. in Solidity source. This is a low false-positive rule because legitimate uses of FHE comparisons almost always go through FHE.select(), not if/require. Any hit requires manual review to confirm whether it's an oracle vulnerability.
QUESTION 07 / 08
In the saturating addition pattern for overflow protection, how does FHE.select(overflow, max255, sum) detect that overflow occurred?
AAfter sum = FHE.add(score, pts), if overflow occurred, sum wraps and becomes less than score. So FHE.lt(sum, score) is true only when overflow happened — this ebool drives the select

DFHE.add() returns a tuple with the sum and an overflow indicator
Correct — A. This is the modular-arithmetic overflow detection trick: if a + b overflows euint8, the result wraps modulo 256 and becomes smaller than a. So (a + b) < a is true if and only if overflow occurred. Applying this: sum = add(score, pts); overflow = lt(sum, score). If overflow is true, we use max (255); if false, we use sum. All in FHE — no plaintext values are revealed.
