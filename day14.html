DApp Design

A sealed-bid auction gives every bidder complete privacy during the bidding phase. No bidder can see any other bid — not even after the auction ends (only the winner and winning amount are revealed). This is impossible with a normal on-chain auction where all storage is public.

Auction Phases

Phase 1
Bidding Open
Bidders submit encrypted bids. Contract tracks encrypted running maximum without revealing any value.
Phase 2
Auction Ended
Owner calls endAuction(). Contract requests Gateway decryption of highest bid handle.
Phase 3
Reveal Pending
KMS processes the decryption request (1–6 seconds). All state locked.
Phase 4
Results Public
Callback fires. Winner and amount public. Losers can claim refunds.

Data Model

FieldTypeVisibilityPurpose
_bidsmapping(address => euint64)PrivateEach bidder's encrypted bid amount
_highestBideuint64PrivateRunning encrypted maximum across all bids
_highestBiddereaddressPrivateAddress of current highest bidder (encrypted)
revealedWinneraddressPublicSet by callback — address of winner
revealedAmountuint64PublicSet by callback — winning bid in plaintext
phaseAuctionPhase (uint8)PublicCurrent phase: Bidding / Ended / Revealed
endTimeuint256PublicUnix timestamp when bidding closes
💡
Why eaddress for Highest Bidder?
If _highestBidder were a plaintext address, observers could track which bidder was "winning" at any point during the auction — leaking information about relative bid sizes. Using eaddress keeps the leading bidder hidden until the reveal.

Smart Contract: SealedBidAuction.sol

State Variables & Setup

Solidity
contracts/SealedBidAuction.sol
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import "fhevm/lib/TFHE.sol";
import "fhevm/gateway/GatewayLib.sol";
import "@openzeppelin/contracts/access/Ownable.sol";
import "@openzeppelin/contracts/utils/ReentrancyGuard.sol";

contract SealedBidAuction is Ownable, ReentrancyGuard {

    // ── Auction state ─────────────────────────────
    enum AuctionPhase { Bidding, Ended, Revealed }

    AuctionPhase public  phase;
    uint256      public  endTime;
    string       public  itemDescription;

    // Encrypted state — never readable on-chain
    euint64      private _highestBid;
    eaddress     private _highestBidder;
    mapping(address => euint64) private _bids;

    // Revealed after callback
    address      public  revealedWinner;
    uint64       public  revealedAmount;

    // Refund tracking
    mapping(address => bool) public refundClaimed;

    // ── Events ────────────────────────────────────
    event BidPlaced(address indexed bidder);
    event AuctionEnded(uint256 requestId);
    event WinnerRevealed(address indexed winner, uint64 amount);
    event RefundClaimed(address indexed bidder);

    modifier onlyGateway() {
        require(msg.sender == GatewayLib.gatewayContractAddress(), "Only gateway");
        _;
    }
    modifier inPhase(AuctionPhase p) {
        require(phase == p, "Wrong auction phase");
        _;
    }

    constructor(string memory description, uint256 durationSeconds)
        Ownable(msg.sender)
    {
        itemDescription = description;
        endTime = block.timestamp + durationSeconds;
        phase   = AuctionPhase.Bidding;

        // Initialise highest bid to 0 so first real bid always wins
        _highestBid    = TFHE.asEuint64(0);
        _highestBidder = TFHE.asEaddress(address(0));
        TFHE.allow(_highestBid,    address(this));
        TFHE.allow(_highestBidder, address(this));
    }
}

placeBid — The Core Logic

The trickiest part: updating the running maximum without branching on the encrypted comparison. We use TFHE.select to obliviously update both the highest bid and the highest bidder.

Solidity
contracts/SealedBidAuction.sol — placeBid
/**
 * @dev Submit an encrypted bid.
 *      The contract obliviously updates the running maximum:
 *        newHighest = isNew > old  ?  newBid  :  oldHighest
 *        newLeader  = isNew > old  ?  msg.sender  :  oldLeader
 *      No branch is taken — both paths computed, one selected.
 */
function placeBid(
    bytes32 encryptedBid,
    bytes calldata inputProof
) external inPhase(AuctionPhase.Bidding) nonReentrant {
    require(block.timestamp < endTime, "Auction has expired");

    euint64 bid = TFHE.asEuint64(encryptedBid, inputProof);

    // Store personal bid (for refund path)
    _bids[msg.sender] = bid;
    TFHE.allow(bid, msg.sender);
    TFHE.allow(bid, address(this));

    // ── Oblivious maximum update ──────────────────
    // isHigher: ebool — true if new bid beats current highest
    ebool isHigher = TFHE.gt(bid, _highestBid);

    // newHighest = isHigher ? bid : _highestBid
    euint64 newHighest = TFHE.select(isHigher, bid, _highestBid);

    // newLeader  = isHigher ? msg.sender : _highestBidder
    eaddress newLeader = TFHE.select(
        isHigher,
        TFHE.asEaddress(msg.sender),
        _highestBidder
    );

    _highestBid    = newHighest;
    _highestBidder = newLeader;

    // This contract needs persistent access to operate on these in future txs
    TFHE.allow(_highestBid,    address(this));
    TFHE.allow(_highestBidder, address(this));

    emit BidPlaced(msg.sender);
}

/// @dev Bidder can re-encrypt and view their own bid
function getMyBid(
    address bidder,
    bytes32 publicKey,
    bytes calldata signature
) external view returns (bytes memory) {
    require(msg.sender == bidder, "Can only view own bid");
    return TFHE.reencrypt(_bids[bidder], publicKey, 0);
}
⚠
Re-bid Replaces Previous Bid
If a bidder calls placeBid twice, their second bid overwrites the first in _bids[msg.sender]. The running maximum already includes their first bid — you may want to restrict bidding to once per address, or handle the delta carefully. The simplest production approach: require(_bids[msg.sender] == 0, "Already bid").

endAuction — Trigger the Reveal

Solidity
contracts/SealedBidAuction.sol — endAuction
/**
 * @dev Called by the owner after bidding closes.
 *      Requests decryption of BOTH the winning bid amount
 *      AND the winning bidder's address in a single batch call.
 */
function endAuction()
    external onlyOwner inPhase(AuctionPhase.Bidding) nonReentrant
{
    require(block.timestamp >= endTime, "Auction not yet expired");
    phase = AuctionPhase.Ended;

    // Grant Gateway permission to decrypt both handles
    TFHE.allowForDecryption(_highestBid);
    TFHE.allowForDecryption(_highestBidder);

    // Batch: decrypt amount (euint64) + bidder address (eaddress) together
    uint256[] memory handles = new uint256[](2);
    handles[0] = euint64.unwrap(_highestBid);
    handles[1] = eaddress.unwrap(_highestBidder);

    uint256 reqId = GatewayLib.requestDecryption(
        handles,
        this.revealCallback.selector,
        0,
        block.timestamp + 1 days,
        false
    );

    emit AuctionEnded(reqId);
}

revealCallback — Store the Result

Solidity
contracts/SealedBidAuction.sol — revealCallback
/**
 * @dev Called by the Gateway after KMS decrypts the results.
 *      Receives: requestId, winning amount, winning address — in handle order.
 *      Note the address comes back as uint256 from the Gateway; cast it.
 */
function revealCallback(
    uint256 /* requestId */,
    uint64  winningBid,
    address winningBidder
) external onlyGateway inPhase(AuctionPhase.Ended) {
    revealedAmount = winningBid;
    revealedWinner = winningBidder;
    phase = AuctionPhase.Revealed;

    emit WinnerRevealed(winningBidder, winningBid);
}

claimRefund — Losers Get Their ETH Back

Solidity
contracts/SealedBidAuction.sol — claimRefund
/**
 * @dev Non-winners reclaim their bid after results are public.
 *      Uses msg.value-based bidding model for simplicity:
 *      bidders send ETH == their bid amount on placeBid.
 *      Winner keeps ETH locked in contract; losers withdraw here.
 *
 *      Privacy note: we check msg.sender != revealedWinner ONLY
 *      after the reveal — during bidding, no refund is possible.
 */
function claimRefund()
    external inPhase(AuctionPhase.Revealed) nonReentrant
{
    require(msg.sender != revealedWinner, "Winner cannot claim refund");
    require(!refundClaimed[msg.sender],   "Already refunded");
    require(address(this).balance > 0,   "No balance");

    refundClaimed[msg.sender] = true;

    // Checks-Effects-Interactions: mark refunded before transfer
    uint256 refund = bidAmounts[msg.sender];  // plain ETH tracking mapping
    bidAmounts[msg.sender] = 0;

    (bool ok,) = msg.sender.call{value: refund}("");
    require(ok, "Transfer failed");

    emit RefundClaimed(msg.sender);
}

Required Test Cases

TypeScript
test/SealedBidAuction.test.ts
import { expect } from 'chai'
import { ethers } from 'hardhat'
import { createInstances } from '../test/instance'
import { getSigners } from '../test/signers'

describe('SealedBidAuction', () => {
  let auction: any, instances: any, signers: any

  beforeEach(async () => {
    signers = await getSigners()
    instances = await createInstances(signers)
    const factory = await ethers.getContractFactory('SealedBidAuction')
    auction = await factory.deploy('Mona Lisa NFT', 3600)  // 1h
  })

  it('T01: bidder can place encrypted bid', async () => {
    const input = instances.alice.createEncryptedInput(auction.target, signers.alice.address)
    input.add64(100n)
    const { handles, inputProof } = await input.encrypt()
    await expect(
      auction.connect(signers.alice).placeBid(handles[0], inputProof)
    ).to.emit(auction, 'BidPlaced').withArgs(signers.alice.address)
  })

  it('T02: highest bidder updates obliviously across multiple bids', async () => {
    // Alice bids 100, Bob bids 200 — Bob should win (without either knowing the other's bid)
    const aliceInput = instances.alice.createEncryptedInput(auction.target, signers.alice.address)
    aliceInput.add64(100n)
    const aliceEnc = await aliceInput.encrypt()
    await auction.connect(signers.alice).placeBid(aliceEnc.handles[0], aliceEnc.inputProof)

    const bobInput = instances.bob.createEncryptedInput(auction.target, signers.bob.address)
    bobInput.add64(200n)
    const bobEnc = await bobInput.encrypt()
    await auction.connect(signers.bob).placeBid(bobEnc.handles[0], bobEnc.inputProof)

    // Advance time past end
    await ethers.provider.send('evm_increaseTime', [3601])
    await ethers.provider.send('evm_mine', [])

    await auction.endAuction()
    // Simulate Gateway callback
    await auction.connect(signers.gateway).revealCallback(0, 200n, signers.bob.address)

    expect(await auction.revealedWinner()).to.equal(signers.bob.address)
    expect(await auction.revealedAmount()).to.equal(200n)
  })

  it('T03: non-gateway caller cannot invoke revealCallback', async () => {
    await expect(
      auction.connect(signers.alice).revealCallback(0, 100n, signers.alice.address)
    ).to.be.revertedWith('Only gateway')
  })

  it('T04: cannot bid after auction expires', async () => {
    await ethers.provider.send('evm_increaseTime', [3601])
    await ethers.provider.send('evm_mine', [])
    const input = instances.alice.createEncryptedInput(auction.target, signers.alice.address)
    input.add64(50n)
    const enc = await input.encrypt()
    await expect(
      auction.connect(signers.alice).placeBid(enc.handles[0], enc.inputProof)
    ).to.be.revertedWith('Auction has expired')
  })

  it('T05: loser can claim refund after reveal', async () => {
    // Setup: Alice bids 100 (loser), Bob bids 200 (winner)
    // ... (place bids, endAuction, revealCallback as in T02)
    const aliceBalBefore = await ethers.provider.getBalance(signers.alice.address)
    await auction.connect(signers.alice).claimRefund()
    const aliceBalAfter = await ethers.provider.getBalance(signers.alice.address)
    expect(aliceBalAfter).to.be.gt(aliceBalBefore)  // net positive after gas
  })

  it('T06: winner cannot claim refund', async () => {
    // After reveal with Bob as winner...
    await expect(
      auction.connect(signers.bob).claimRefund()
    ).to.be.revertedWith('Winner cannot claim refund')
  })

  it('T07: WinnerRevealed event emitted with correct values', async () => {
    // ...setup bids, end, then:
    await expect(
      auction.connect(signers.gateway).revealCallback(0, 200n, signers.bob.address)
    ).to.emit(auction, 'WinnerRevealed')
      .withArgs(signers.bob.address, 200n)
  })
})

usePlaceBid Hook

TypeScript
hooks/usePlaceBid.ts
'use client'
import { useState } from 'react'
import { useAccount, useWriteContract } from 'wagmi'
import { getFhevmInstance } from '../lib/encrypt'
import { AUCTION_ADDRESS, AUCTION_ABI } from '../lib/contract'

export function usePlaceBid() {
  const [status, setStatus] = useState<'idle' | 'encrypting' | 'pending' | 'done' | 'error'>('idle')
  const [txHash, setTxHash] = useState<string | null>(null)
  const { address } = useAccount()
  const { writeContractAsync } = useWriteContract()

  async function placeBid(amountWei: bigint) {
    if (!address) return

    try {
      // Step 1: Encrypt the bid amount in the browser
      setStatus('encrypting')
      const instance = await getFhevmInstance()
      const input = instance.createEncryptedInput(AUCTION_ADDRESS, address)
      input.add64(amountWei)
      const { handles, inputProof } = await input.encrypt()

      // Step 2: Send transaction with encrypted bid + ZK proof
      setStatus('pending')
      const hash = await writeContractAsync({
        address: AUCTION_ADDRESS,
        abi: AUCTION_ABI,
        functionName: 'placeBid',
        args: [handles[0], inputProof],
        value: amountWei,   // ETH deposit equal to bid (for refund path)
      })
      setTxHash(hash)
      setStatus('done')
    } catch (e) {
      console.error(e)
      setStatus('error')
    }
  }

  return { placeBid, status, txHash }
}

useAuctionResult Hook

TypeScript
hooks/useAuctionResult.ts
'use client'
import { useState, useEffect } from 'react'
import { useConfig } from 'wagmi'
import { watchContractEvent } from 'wagmi/actions'
import { AUCTION_ADDRESS, AUCTION_ABI } from '../lib/contract'

interface AuctionResult {
  winner: string
  amount: bigint
}

export function useAuctionResult() {
  const [result, setResult] = useState<AuctionResult | null>(null)
  const [isRevealing, setIsRevealing] = useState(false)
  const config = useConfig()

  useEffect(() => {
    const unwatch = watchContractEvent(config, {
      address: AUCTION_ADDRESS,
      abi: AUCTION_ABI,
      eventName: 'WinnerRevealed',
      onLogs: (logs) => {
        const [log] = logs
        if (log.args.winner && log.args.amount !== undefined) {
          setResult({ winner: log.args.winner, amount: log.args.amount })
          setIsRevealing(false)
        }
      },
    })
    return () => unwatch()
  }, [config])

  // Call this when endAuction tx confirms — shows "waiting for reveal" UI
  function markRevealPending() { setIsRevealing(true) }

  return { result, isRevealing, markRevealPending }
}

UI State Machine

The frontend has four distinct UI states that map directly to the contract's AuctionPhase:

PhaseUI StatePrimary ActionKey Elements
Bidding Active auction Show bid form Countdown timer, BidForm component, "Your bid is private" notice
Ended Awaiting reveal Owner: "End Auction" button Spinner + "Decryption in progress…" message, estimated wait time
Reveal pending KMS processing Disabled — waiting Animated progress bar, "KMS decrypting result (1–6 seconds)…"

Privacy Guarantees & Limitations

What is PrivateWhat is PublicLimitation
Every individual bid amount The fact that an address placed a bid Participation is visible on-chain via BidPlaced events
The leading bidder during bidding Winning bid amount (after reveal) The winning amount becomes permanently public
All losing bid amounts (never revealed) Winner's address (after reveal) Winner identity is public; privacy only for losers post-auction
Running maximum calculation Number of bidders Transaction count leaks participation metadata
💡
This Is Much Better Than Public Auctions
In a standard on-chain auction, every bid is visible in real time. Bidders can simply outbid the current leader by 1 wei. FHEVM's sealed-bid model forces everyone to commit their true valuation — delivering the auction-theory ideal of truthful bidding.

Day 14 Quiz
7 questions · sealed-bid auction DApp
QUESTION 01 / 07
Why is the current highest bidder stored as eaddress rather than a plain address?
ATo save gas by compressing address storage
BThe Gateway requires eaddress for its decryption callback
CA plaintext address would allow observers to track which bidder is winning in real time, leaking information about relative bid sizes
DSolidity cannot store addresses in mappings without encryption
Correct — C. If the leading bidder were public, observers could infer that anyone who becomes the leader must have bid higher than the previous leader. Over multiple bids, this leaks comparative information. Encrypting the leader keeps the field entirely private until the reveal.
QUESTION 02 / 07
In placeBid, why must you use TFHE.select(isHigher, bid, _highestBid) to update the maximum, instead of if (TFHE.decrypt(isHigher)) { _highestBid = bid; }?
ATFHE.decrypt is not available in Solidity
BDecrypting inside placeBid would reveal whether the new bid is higher, breaking bid privacy for every transaction
CTFHE.select is cheaper in gas
DThe if-statement would revert on an ebool
Correct — B. Decrypting inside placeBid would leak whether the new bid beat the previous maximum — revealing comparative information to anyone watching the transaction outcome. TFHE.select performs the update homomorphically, keeping both bids secret throughout.
QUESTION 03 / 07
The endAuction function requests decryption of two handles: _highestBid and _highestBidder. What must the callback signature look like?
ArevealCallback(uint256 requestId)
BrevealCallback(uint64 amount, address winner)
CrevealCallback(uint256 requestId, bytes[] results)
DrevealCallback(uint256 requestId, uint64 winningBid, address winningBidder)
Correct — D. The callback receives: (1) requestId first, (2) plaintext values in the same order as the handles array. Handle 0 was _highestBid (euint64 → uint64), handle 1 was _highestBidder (eaddress → address). So: revealCallback(uint256, uint64, address).
QUESTION 04 / 07
In the frontend usePlaceBid hook, why is value: amountWei passed alongside the encrypted bid?
AThe ETH is the actual payment deposited so losers can claim a refund later — the encrypted bid amount determines who wins, but the ETH value is what gets held in escrow
BThe FHEVM node charges ETH for encryption
CWithout value, the ZK proof fails
DIt is required by the Gateway for decryption fees
Correct — A. The encrypted bid value determines who wins (via homomorphic comparison). The ETH deposit is a separate mechanism: the contract holds it on behalf of the bidder, and losers can call claimRefund to get it back after the reveal.
QUESTION 05 / 07
Which privacy guarantee does this sealed-bid auction NOT provide?
ALosing bid amounts are never revealed
BThe running leader is hidden during bidding
CThe fact that an address participated is hidden
DIndividual bid values are hidden during bidding
Correct — C. The BidPlaced(address indexed bidder) event reveals that an address participated. On-chain, anyone can see which addresses called placeBid and the transaction count. Participation metadata is inherently public in this design.
QUESTION 06 / 07
What is the correct order of operations when a bidder submits a bid from the frontend?
ASend tx → wait for confirmation → encrypt the amount client-side → include in next tx
BEncrypt amount + generate ZK proof in browser → send tx with (handles[0], inputProof) as args → await tx confirmation
CRequest encryption from the FHEVM node → node returns ciphertext → include in tx
DSign the amount with EIP-712 → send to the Gateway → Gateway encrypts and forwards to contract
Correct — B. All encryption happens client-side using fhevmjs before the transaction is sent. The browser generates both the ciphertext (handles[0]) and the ZK proof (inputProof). The transaction carries both as calldata. No additional round-trips to any server are needed.
QUESTION 07 / 07
After endAuction() is called, the UI should show "waiting for reveal." How should the frontend know when the reveal is complete?
APoll auction.phase() every 500 ms
BWait a fixed 10 seconds — the KMS always responds within this time
CCheck the Gateway contract for a DecryptionFulfilled event
DSubscribe to the WinnerRevealed event on the auction contract using watchContractEvent before calling endAuction
Correct — D. Subscribe to the event before sending the endAuction transaction to avoid race conditions. When the Gateway callback executes, your contract emits WinnerRevealed, the wagmi listener fires, and you update the UI — no polling required.
